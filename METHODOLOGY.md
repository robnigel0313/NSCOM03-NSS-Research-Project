# Technical methodology contribution

The study uses a discrete-event simulation to examine how predefined traffic imbalance across two parallel Ethernet transmission paths affects payload throughput, frame delay, frame loss and link utilization. Each path is modeled as a single-server FIFO queue with Poisson arrivals, deterministic service time and finite capacity (an M/D/1/101 system, including the frame in service). The paths operate independently at 100 Mbps each, with no reassignment of traffic between them. Full-duplex operation is assumed, but only one transmission direction is modeled.

Each generated frame carries a 1,500-byte payload. The modeled link occupancy is 1,538 byte-times, accounting for the Ethernet header, frame check sequence, preamble, start-frame delimiter and interframe gap. This corresponds to a service interval of 123.04 microseconds and a delivery interval of 122.08 microseconds, excluding the trailing interframe gap. The resulting effective payload capacity is approximately 97.53 Mbps per link. The assigned offered payload rate is converted to frames per second by dividing the rate in bits per second by 12,000 bits. Independent exponential interarrival times are generated using reproducible pseudorandom streams derived from each run seed.

An arriving frame is admitted immediately if its assigned link is idle. If the link is busy, the frame enters the waiting queue when space is available. A frame is discarded only if all 100 waiting positions are occupied. Consequently, congestion can increase waiting time without necessarily causing frame loss. Transmission speed remains constant regardless of queue occupancy.

The experimental design crosses three offered payload loads (80, 120 and 160 Mbps) with three traffic distributions (50/50, 70/30 and 90/10), yielding nine configurations. Each configuration is repeated using ten predefined seeds. Both queues begin empty, and arrivals are generated for 60 simulated seconds without a warm-up period. After the observation period, accepted frames are allowed to finish. Throughput and link utilization are restricted to the observation interval; frame loss is based on observation-period arrivals, while average delay includes all accepted frames after draining. Epoch timestamps are generated by adding simulated event times to a Unix epoch reference captured once per run. These timestamps are synthetic rather than measurements of actual traffic.

The model does not implement a complete IEEE 802.1AX link aggregation protocol, dynamic load balancing, flow hashing, MAC learning, retransmissions, Ethernet PAUSE, propagation delay, processing delay or physical-layer errors. Findings therefore apply to the specified queueing and transmission model, not to all operational Ethernet aggregation systems. Instructor confirmation of this scope remains necessary.
